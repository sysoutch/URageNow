## Priority 1: Secure Distributed Runtime

1. Add a restricted runtime agent on each remote bot host. It must only start declared runtimes and return redacted status; it must not accept arbitrary commands, paths, or environment values.
2. Authenticate dashboard-to-agent traffic using TLS identity and rotating credentials. Shared secrets over plain LAN HTTP remain development-only compatibility support.
3. In progress: global, Image, and 3D OpenAI-compatible API keys plus dashboard, remote-worker, messenger-admin, Telegram, Matrix, and WhatsApp credentials support native credential storage for dashboard-launched and standalone Messenger runtimes. API keys are redacted from dashboard responses and excluded from future dashboard-settings writes. Dashboard settings and status APIs must contain only secret references and redacted state.
4. Provide service installation and health checks for Windows Service, systemd, and launchd under dedicated runtime identities.

## Priority 2: LLM Configuration Cleanup

1. Completed first migration step: prefer `OPENAI_COMPATIBLE_*` environment variables while retaining `LMSTUDIO_*` aliases.
2. Rename persisted dashboard and API fields from `lmStudio*` to provider-neutral names with a one-way migration from existing settings files.
3. Separate generic OpenAI-compatible behavior from LM Studio-only model lifecycle and stateful-chat capabilities.
4. Add provider contract tests against Ollama, LM Studio, and llama.cpp fixtures.
