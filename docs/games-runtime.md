# Runtime-importable games

Games are registered as declarative packages under the dashboard's **Games** view. The catalog records compatibility and enabled state separately for Discord, Telegram, Matrix, and WhatsApp. Import, enable/disable, and delete operations update the shared application data directory so the dashboard and messenger runtime see the same catalog.

An import file is a UTF-8 JSON object with this shape:

```json
{
  "manifest": {
    "id": "token-typing",
    "name": "Token Typing",
    "description": "Guess a hidden text-generation speed.",
    "version": "1.0.0",
    "runtimes": ["discord"],
    "gameType": "typing-speed"
  },
  "configuration": {
    "rounds": 5,
    "textMode": "sequential",
    "texts": [
      "A sample passage of at least twenty words for the first animated typing round. Every player watches the same preview and estimates how many tokens appear each second.",
      "A different sample passage of at least twenty words for the next round. The dashboard can edit, add, or remove passages after the package has been installed."
    ]
  }
}
```

The current package cap is 128 KiB; IDs are lowercase slugs; two game types are implemented: `typing-speed`, with 1–10 rounds and 1–30 texts, and `animal-racing`, with 1–10 rounds and 1–10 rosters of 3–8 racers each. Each text needs 20–100 words and at most 600 characters; shorter text makes the hidden typing speed impossible to judge. `textMode` may be `sequential` (in list order, looping), `random` (independent choice, repeats possible), or `shuffle` (all texts used once before reshuffling). Existing packages with one `text` remain valid and behave as a one-item sequential list. Racing packages set `rounds` (1–10), `rosterMode` (`sequential`, `random`, or `shuffle`), `houseFee` (0–30 percent), `bonusPool` (0–100,000 credits), and `rosters`. Each roster declares `species` (`horse`, `penguin`, or `emu`); every racer needs a unique name, a `#rrggbb` `color`, and a `power` from 1–10 that sets its win chance. Packages saved before `species` was added infer it from conventional Penguin/Emu roster labels and otherwise use horses. In the dashboard, open **Games → Installed games → Edit texts** for typing packages or **Games → Installed games → Edit rosters** for racing packages to edit the installed copy; saving does not change games already in progress. A package cannot execute JavaScript or access the bot process. Additional mechanics require a reviewed adapter in the target runtime before packages of that type can run. A package may declare multiple compatible runtimes, but each runtime must implement its `gameType` and be enabled explicitly.

The Discord adapter recreates the source simulator's hidden 5–150 tokens/second rounds, uses 1 word = 1.3 estimated tokens, and scores each player's percentage error independently. `/game` opens the enabled package picker. The host chooses the round count in a Discord modal; the animated text comes from the dashboard's saved list. Each player submits one numeric guess per round. The bot acknowledges each submission in the channel without showing its value and sends the player a private receipt. Only the host can advance or end the game. Advancing reveals the previous round's actual speed. Finishing leaves the last GIF message in place and posts a separate results embed with actual speeds and a field for each player's guesses, round scores, and average accuracy. Long leaderboards are split across multiple embeds and messages. The preserved GIF's buttons remain visible but reject further actions after the session ends.

Derby Lab (`animal-racing`) starts from `/game`; the host first chooses horses, penguins, or emus from the species available in the saved rosters, then sets the round count (1–10) in a modal. Each round draws only from rosters for that species in the configured `rosterMode`. The host's panel offers **Place my bet**, **Show board**, **Start race (host)** or **Final race (host)**, and **Cancel game (host)**. Bets stay private: tapping **Place my bet** replies with an ephemeral select menu of that round's racers showing each win chance and strength (strength is `power` raised to 2.3, so a strong racer is favoured but never guaranteed), and the selected racer opens an ephemeral modal for one whole-credit amount from 1 to 1,000,000. A player may bet on several different racers; selecting the same racer again updates that racer's bet without removing their other bets. **Show board** replies privately with the player's bets, public stake totals, the purse, and the house fee. Only the player who started the derby can cancel it. A winning credit returns `(total staked + bonus pool) × (1 − houseFee%)` divided by the total staked on the winner, so the multiplier is shown in the bet menu and every losing bet loses its stake. Each round disables the old message's controls while preserving its content and attachment, then posts the new animated GIF replay as a separate Discord message. The selected winner is always given the first finish rank in that replay. Replays show species-specific art, a 3–2–1–START countdown before movement, and a three-second winner screen. The bot posts the textual result and next-round controls only after the GIF's first 12.125-second playback finishes. SVG frames are rasterized by Sharp and assembled by FFmpeg; output is capped at 7 MiB, validated as a real GIF, and temporary frames are removed after success or failure. A finished game posts its final replay separately and then a final-ledger embed with a leaderboard and one field per player listing every bet's round, racer, stake, payout, and net credits, split across embeds when Discord's 20-field or text limits are reached. `scripts/preview-derby-lab-gif.ts` renders one saved roster's replay to `bots/discord-bot/derby-lab-preview.gif` for previewing the animation; it takes a roster index and a finisher index and is not part of `check:games`.

Ultimate Texas Hold'em (`ultimate-texas-holdem`) opens from `/game` with an ephemeral ante menu built from the package's `anteOptions` (1–8 whole credits) and an optional Blind menu, then a modal that sets the hand count (1–20). Up to six seats join with **Sit down** or **Sit down + Blind**, and each seat receives exactly two hole cards. Hole cards are the only private state in this game: they are delivered through a direct message and never rendered on the public board, and a seat whose cards cannot be delivered is released so unseen cards never score at showdown. The public table reveals the community in two steps — the flop once a seat has made its preflop decision, and the turn and river once every seat has acted, so the postflop decision always sees all five cards — and turns the dealer's two cards face up only after every seat is settled. Preflop actions are **Play** (3× ante), **Call** (1× ante), or **Fold**; postflop actions are **Bet** (2× ante) or **Check**. The dealer qualifies with an Ace or King high; a non-qualifying dealer pushes the ante and loses Play, Bet, and Blind even money. Trips settle from the player's own best five-card hand against the configurable paytable, although no seat currently places a Trips side bet, so that bonus stays at zero. **Next hand** re-deals and **End game** publishes final standings without dealing more cards. `scripts/check-discord-ultimate-texas-holdem.ts` drives that whole flow against a scratch package and asserts hole cards never leak into any public reply, every action button carries a table-scoped custom ID, and every modal input is labelled.



Discord routes every game interaction to the adapter registered for the `gameType` of the installed package, and each adapter independently ignores interactions owned by another game type; an adapter never answers on behalf of a foreign game, so an invalid package configuration returns one private failure notice instead of a generic error. `scripts/check-discord-game-start-routing.ts` asserts that contract with mocked modal submits, button presses, and racer picks, and runs inside `check:games`. Discord also validates the posted component JSON: every modal text input needs a non-empty `label`, otherwise the modal POST is rejected with `50035 …label[BASE_TYPE_REQUIRED]` and the player sees only the generic failure notice, so that check drives the Derby Lab bet flow far enough to catch a missing label.

Discord application commands are not published automatically when the bot starts. After adding or changing a slash command, run `npm --prefix bots/discord-bot run register` with the bot token and client ID configured. Existing command-settings files are migrated to enable newly added commands once; later dashboard toggles are preserved.

The Discord GIF renderer requires FFmpeg at the configured `FFMPEG_EXECUTABLE_PATH` and Sharp. It uses a ready frame, speed-dependent typing frames, and a completed hold so fast rounds remain visible. It rejects output larger than 7 MiB and removes temporary frame files after success or failure. Invalid, unsupported, duplicate, oversized, or incompatible packages are rejected by the dashboard API. Disabling or deleting a package ends its active game sessions on their next interaction. Session state is process-local and expires after 15 minutes; a bot restart ends active games.
